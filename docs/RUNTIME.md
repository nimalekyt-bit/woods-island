# Runtime Woods Island

Production-интерфейс находится в `runtime/`. Vite собирает четыре окна:
`index.html`, `settings.html`, `overlay.html`, `editor.html`.
Настройки и редактор изображений создаются по запросу и освобождают WebView при закрытии.
`frontend/` сохранён как архив исходного дистрибутива; сборка его не копирует.
React-прототип в `src/` запускается отдельно и не входит в EXE.

## Разработка

- `pnpm dev` — тот же runtime с обновлением страницы после изменения исходников.
- `pnpm build` — проверка IPC, TypeScript, Vite, UTF-8/imports и manifest SHA256.
- `pnpm generate:ipc` — обновление контрактов после изменения команд Rust или настроек.
- `pnpm check:runtime` — проверка соответствия контрактов и готового `dist/`.
- `pnpm test:runtime-state` — регрессии геометрии, событий, персонажей и паузы с точными часами.
- `cargo build --release --manifest-path src-tauri/Cargo.toml` — EXE со встроенным `dist/`.
- Для карт исходников в PowerShell задайте `$env:WOODS_SOURCEMAP='1'` перед сборкой.

## Структура

`runtime/components/` содержит читаемые компоненты вопросов Claude, иконок,
настройки экспорта в Obsidian и редактора заметок. Редактор загружается при открытии
заметок; его библиотека не входит в начальный граф загрузки пилюли.

`runtime/ipc/generated.ts` генерируется из зарегистрированных Rust command signatures
и `default_settings`; сборка прекращается при расхождении. Rust `Value` обозначен
как `JsonValue`, без выдуманной схемы. `client.ts` уточняет контракты настроек
и ответов Claude; `legacy-api.ts` связывает существующие вызовы с типизированным IPC.

`runtime/compat/` — восстановленный и отформатированный код приложения.
Основные функции именованы (`IslandApp`, `useRuntimeEvents`, `useIslandGeometry`,
`HomePlayer`, `LyricsPanel`, `Launcher`, `useIslandStore`). Миграция постепенная:
оставшиеся локальные сокращения и динамические payloads переводятся по мере изменения
соответствующих модулей. Проверка `checkJs` для слоя совместимости пока отключена.

`runtime/vendor/` сохраняет согласованные версии React 19/ReactDOM, Framer Motion
и ProseMirror/Tiptap из дистрибутива. Новые компоненты используют тот же экземпляр
React через `runtime/react.ts`. React 18 отдельного прототипа не импортируется
в production. Атрибуция зависимостей — в THIRD_PARTY_NOTICES.md.

`runtime/characters/catalog.ts` содержит типизированный реестр, локализацию и геометрию
25 персонажей; `selection.ts` — выбор персонажа для покоя/музыки и политику формы.
«Обычный/Крупный» задаёт размер персонажа. Для простой формы выберите «Без персонажа»:
этот выбор имеет приоритет над `liquidWith`. Отдельный музыкальный персонаж действует
только при воспроизведении и возвращается к обычному сразу при паузе.

`runtime/island/sizing.ts` рассчитывает размеры виджетов и normal/title/lyrics/player.
`geometry.ts` задаёт приоритет режимов, размеры уведомлений, palette/chat и drag overlay;
`transitions.ts` — параметры пружин и выбор перехода. `useIslandGeometry` в compat
содержит подписки store и измерение home/agentAsk, затем вызывает чистый TS расчёт.

`runtime/island/interactions.ts` управляет hover, outside click, palette, горячей
клавишей и удержанием окна webAI через явные порты store. Таймеры отменяются при
переключении режима и размонтировании; условия повторно проверяются в момент срабатывания.
Обработчики остальных функций (capture, VPN, OBS и другие) пока остаются в compat.

`runtime/media/activity.ts` сохраняет музыкальную пилюлю на 2500 мс с начала паузы.
Повторные метаданные не продлевают таймер; resume отменяет его. Затем начинается
анимация уменьшения. В `components/CollapsedTrack.tsx` находятся название трека,
значок паузы и прогресс без движения при паузе; обычная media-пилюля использует тот же значок.

`runtime/media/events.ts` обрабатывает metadata/cover: обложка может прийти до трека,
предыдущая сохраняется до получения новой или тайм-аута 4000 мс. Запоздавший расчёт
accent не применяется к другому треку. Таймеры cover и pause освобождаются вместе.
`NormalMediaPill.tsx` и `LyricsMediaPill.tsx` содержат музыкальную разметку. JS адаптеры
передают существующие виджеты как ReactNode; lyrics сохраняет ширину по всему тексту
песни, viewport 30 px и смену строк за 240 мс. При выходе из lyrics lineW сбрасывается.

## Добавление персонажей

Персонажи — процедурные SVG, без видео или GIF. Реализации `build` создают SVG-узлы,
`draw` обновляют их по времени, курсору, настроению и измеренному уровню звука.
Рисование пока находится в `runtime/compat/island-store.js`; перенос каталога
не означает, что весь этот модуль уже типизирован.

Для нового персонажа нужны уникальный `id`, SVG-реализация `build`/`draw`, имя/описание
RU/EN и границы рисунка. Реализация включается в соответствующий список drawings
или renderers, который получает `createCharacterCatalog`. Настройки строятся из каталога,
поэтому новый элемент доступен также как музыкальный персонаж. После добавления
проверяются музыка/пауза, cursor/sleep, масштаб и clipping; одновременно работает
выбранный персонаж. Для экономии ресурсов следует переиспользовать SVG-узлы в `draw`.
Формат импорта произвольных персонажей пользователем пока не реализован.

`runtime/diagnostics.ts` экспортирует store/API для нативной приёмки через стабильный
`/assets/runtime-debug.js`; код этого общего store также используется приложением.

## Приёмка

`pnpm test:native` запускает реальный WebView2/Tauri с отдельным временным профилем
и `WOODS_ISLAND_PASSIVE_QA=1`. Проверяются окна, сохранение, настройки, музыка,
PPTX, single/multi-select Claude и Store inventory/icons. Запуск личных приложений,
VPN connect, аппаратный ввод и фокус в приёмке не инициируются.

`pnpm test:performance -- <baseline.exe> <candidate.exe>` последовательно сравнивает
CPU/working set/private bytes всей группы процессов, включая WebView2 скрытых окон.
Музыка подаётся как локальная metadata fixture; текущий системный аудиовыход наблюдается
без изменения воспроизведения и громкости. Отчёт фиксирует условия и ограничения.
