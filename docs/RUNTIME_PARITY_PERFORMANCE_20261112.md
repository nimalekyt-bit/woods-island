## Production frontend

Четыре окна собираются Vite из `runtime/`. `frontend/` сохранён как архив;
React-прототип `src/` запускается отдельно. Производственная сборка не копирует
архивные модули. `pnpm dev` работает с теми же исходниками, которые входят в EXE.

`runtime/compat/` содержит восстановленный, отформатированный код приложения.
Основные компоненты и hooks получили понятные имена. Новые `AgentQuestion`,
`ProgramIcon`, `ObsidianVaultSettings` и `LazyNoteEditor` выделены в компоненты.
Миграция продолжается: локальные сокращения и динамические payloads остаются
в совместимом JavaScript, `checkJs` этого слоя отключён.

IPC генерируется из 161 зарегистрированной Rust-команды и 122 настроек.
Сборка проверяет расхождение сигнатур. Настройки и ответы Claude уточнены
в типизированном клиенте; Rust `Value` честно обозначен как `JsonValue`.
Полной типизации всех событий и схем backend пока нет.

React/ReactDOM 19.3.0, Motion и редактор выделены в vendor-модули.
Новые компоненты используют один React через `runtime/react.ts`.
Явный classic JSX исключает попадание React 18 JSX runtime из прототипа.
Диагностический entry сохраняет публичные exports; lazy Settings/Stage использует
импорты исходников без старой карты путей Vite.

Основной модуль: 251 064 байта вместо архивных 650 715. Это разделение кода;
все JS-файлы новой сборки вместе занимают 1 394 913 байт. Библиотека редактора
(393 898 байт) загружается при открытии заметок. Нативный тест проверяет отсутствие
её загрузки до заметок и наличие после открытия, затем экспорт Markdown без перезаписи.

## Функции

- PPTX: текст извлекается в порядке relationships презентации, сохраняются
  Unicode, сущности, абзацы и переносы. Ограничены ZIP/XML размеры, запрещены
  внешние и выходящие из архива пути. Вложения используют существующий AI pipeline.
  Это извлечение текста; бинарные PPT и визуальный рендер слайдов не добавлены.
- Claude `AskUserQuestion`: одиночный и множественный выбор, несколько вопросов,
  массивы labels с запятыми. Проверяются точные keys/options/cardinality/expiry.
  Hook возвращает `decision.behavior=allow` и `updatedInput.answers`, сохраняя
  исходные поля tool input. UI закрывает вопрос после успешного native ответа.
- Windows Store: inventory через Shell AppsFolder, launcher хранит AUMID,
  запуск реализован через `IApplicationActivationManager`. EXE/LNK/Store иконки
  извлекаются Windows Shell в PNG. Inventory, иконки и persistence проверяются;
  фактическая активация личных Store-приложений исключена из пассивной приёмки.
- VPN: Windows RAS, WARP, зарегистрированные туннельные службы AmneziaWG/WireGuard
  и пользовательские команды. Переключение службы ждёт целевого SCM-состояния,
  ошибки доступа возвращаются пользователю. Состояние службы не доказывает
  успешность интернет-маршрута. Для custom `onSource=command` означает последнюю
  успешную команду; состояние туннеля не опрашивается, после перезапуска сбрасывается.
- Установленные GUI-клиенты AmneziaWG, Hiddify, Proton VPN, Radmin VPN, v2RayTun,
  WireGuard доступны через «Открыть». Для клиентов без управляемого API автоматическое
  подключение не заявляется; нужны служба или настроенные команды.

## Оптимизация

Downloads snapshot входит в bootstrap; события отправляются при изменениях.
Controls UI использует initial snapshot и `controls:changed` вместо своего таймера.
Общий native монитор по-прежнему обновляет управление раз в 3 секунды.
Иконки ограничены кэшами: UI 128, backend 256; запросы UI дедуплицируются.
Inventory программ кэшируется на 60 секунд.

Окна настроек и редактора изображений не создаются при запуске (`create=false`).
Они создаются из той же Tauri-конфигурации по запросу, а закрытие освобождает
WebView renderer. Создание выполняется вне UI-потока; параллельные запросы
сериализуются. Настройки и исходник изображения остаются в native storage.
Overlay захвата остаётся готовым к событиям; его lifecycle не изменён.
Нативная приёмка проверяет отсутствие двух окон на старте и их повторное создание
после закрытия с восстановлением данных, нужного раздела и без фокуса в QA.

Файлы агентов перечитываются при изменении metadata, удалённые записи уходят
из кэша. Не более 1000 файлов; idle scan/heartbeat — 1 секунда, pending — 400 мс.
При отсутствии аудиопакетов FFT не вычисляется. В тишине polling — 32 мс вместо
10 мс; нулевые bands/level не повторяются. Ненулевой, включая устойчивый, спектр
сохраняет периодические события, поскольку UI проверяет `bandsAt`.

Нативная приёмка использует отдельные временные профили без аппаратного ввода
и фокуса. Музыка, погода, AI и OBS проверяются протокольными fixtures; личные
приложения и VPN-подключения не запускаются. Живой Yandex connector повторно
не проверяется на изолированном порту. Проверка настроек не означает исполнение
shutdown, сети, вставки в чужие приложения или запросов к личным провайдерам.

Performance сравнивает сохранённый EXE TASK-1416 и candidate последовательно.
CPU суммирует native и всех descendants WebView2; приводится процент всей машины
и одного ядра. Private bytes суммируются; working set может учитывать разделяемые
страницы несколько раз. Два сценария — покой и музыка с loopback metadata fixture;
наблюдение системного аудиовыхода не меняет музыку или громкость владельца.
Это короткие замеры в текущем окружении, без доказательства нагрузки всех функций.
